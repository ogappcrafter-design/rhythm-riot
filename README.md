# Rhythm Riot 🎚️

A lane-based **rhythm-tap** game with one thing almost nobody in the genre does: the game's
own visuals shift in real time based on **how well you're playing**. A great run doesn't just
score higher — it *looks and feels* different, because you're pushing a hidden **Mood Meter**
up or down as you play.

Built on **React + Vite + TypeScript**, wrapped for Android with **Capacitor**. Gameplay
renders on a single `<canvas>` for performance; the whole UI is custom-styled (word-art
titles, illustrated icons, per-song palettes — no plain system text or stock icons).

---

## Quick start

```bash
npm install
npm run dev        # dev server at http://localhost:5173
npm run build      # typecheck + generate charts + production build to dist/
npm run preview    # serve the production build
npm test           # chart-pipeline validation suite (node --test)
```

> **Audio:** the five track `.mp3`s are not committed. Drop them into `public/audio/`
> (see `public/audio/README.md` for exact filenames). Without them the game runs in a
> designed **silent mode** — everything works, it just makes no sound.

## How it's put together

```
src/
  data/            track catalog, per-song palettes, raw librosa analysis
  charts/          GENERATED chart JSON (one per track) + manifest — committed, never edited by hand
  engine/          the game core (framework-agnostic, no React)
    audioClock     audio-synced clock w/ performance.now() fallback
    chartTypes     the chart schema (spec §5.4)
    chartLoader    lazy per-track chart loading (Vite glob) + mood-curve sampling
    grading        timing windows → Perfect/Great/Good/Miss, score, letter/star grade
    moodSystem     the 0–100 inertial Mood Meter + Vibe Score  ← the differentiator
    particles      "riot shards" particle field (mood-scaled density)
    colors         palette interpolation (mood-driven color grading)
    gameEngine     the canvas render + input + scoring loop
  audio/sfx        synthesized Web Audio SFX (zero audio assets needed)
  state/           localStorage persistence + React app context (nav + live settings)
  components/       WordArt (SVG), icons (SVG), shared UI, ErrorBoundary
  screens/         intro · menu · song select · ready · gameplay · results · settings · help · calibration
scripts/
  generateCharts.mjs   build-time chart generator (runs automatically on `npm run build`)
test/
  charts.test.mjs      37 assertions over the generated charts + determinism check
```

### The Mood System (the point of the game)

`src/engine/moodSystem.ts` holds a hidden `0–100` meter with **inertia** — performance sets a
*target*, and the live value eases toward it over ~1–2s so mood changes feel like a wave, not a
switch. Streaks (especially Perfects) push it up; misses pull it down. Every frame the renderer
reads the live value and interpolates the entire look — background color grade, particle density
& speed, note glow, hit-zone brightness, parallax pulse, and the combo counter's weight/glow.
Mood is *purely a response* to performance; it never feeds back into note timing or difficulty.

A second hidden number, the **Vibe Score**, measures how cleanly you rode the song's own energy
arc (from the chart's `moodCurve`) — the "secret premium stat" shown on the results screen.

### Chart pipeline

Charts are **generated at build time**, never on-device, in two stages:

1. **`scripts/analyze.py`** runs `librosa` over the real audio in `public/audio/` and writes
   `scripts/analysis_real.json` — the full beat grid, every detected onset (with strength +
   local energy), and the normalized RMS energy envelope. (Decodes `.m4a`/`.mp3` via the ffmpeg
   binary bundled with `imageio-ffmpeg`; no system ffmpeg needed.)
   Regenerate with: `pip install librosa imageio-ffmpeg && python3 scripts/analyze.py`.
2. **`scripts/generateCharts.mjs`** turns those real onsets into per-difficulty charts. Notes are
   anchored to actual detected hits (Hard lands on the real onset times), not a synthesized grid:

- **Easy** — 3 lanes, ~50% of onsets, strong beats only, ≥250 ms spacing
- **Medium** — 4 lanes, ~75% of onsets
- **Hard** — 4 lanes, 100% of onsets incl. sub-beat syncopation, tighter windows
- **Expert** — 5 lanes, denser + flourishes on drops. **Locked** until you hit ≥90% Perfect on
  Hard for that track. Marked `autoGenerated: true` — per spec §5.3 these are scaffolding meant
  to be hand-passed by ear before shipping as "final" Expert; the schema is human-readable so you
  can hand-edit the JSON directly.

The generator is **seeded**, so regenerating produces byte-identical output (the test suite
enforces this). Change the generator → re-run `npm run gen:charts` → commit the new charts.

### Adding a song (no code changes — spec §5.5)

1. Add an entry to `TRACKS` in `src/data/tracks.ts` and a palette in `src/data/palettes.ts`.
2. Add its analysis numbers to `ANALYSIS` in `scripts/generateCharts.mjs`, run `npm run gen:charts`.
3. Drop `<trackId>.mp3` into `public/audio/`.

That's it — song select, loading, difficulty gems and unlock logic all scale automatically.

## Android / Google Play

The native Android project is created by Capacitor and is **git-ignored** (regenerate anywhere):

```bash
npm run build
npx cap add android          # first time only — creates android/
npx cap sync android         # copy the latest web build into the native project
npx cap open android         # open in Android Studio
```

**Portrait lock** (rhythm games are unplayable in the wrong orientation): in
`android/app/src/main/AndroidManifest.xml`, add to the main `<activity>`:
`android:screenOrientation="portrait"`.

### Release build (AAB) + deobfuscation / mapping file

1. In Android Studio: **Build → Generate Signed Bundle / APK → Android App Bundle**, create/select
   your upload keystore, choose the **release** variant.
2. Enable R8 shrinking so you ship a small, obfuscated binary. In `android/app/build.gradle`:
   ```gradle
   buildTypes {
       release {
           minifyEnabled true
           shrinkResources true
           proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
       }
   }
   ```
3. R8 then emits the **deobfuscation (mapping) file** at
   `android/app/build/outputs/mapping/release/mapping.txt`. **Upload this to the Play Console**
   (App bundle explorer → the release → *Upload deobfuscation file*) so crash stack traces come
   back readable. Keep every release's `mapping.txt` — each build's is unique.
4. Upload the `.aab` to a **testing track** (Internal → Closed → Open) before Production. Bump
   `versionCode`/`versionName` in `android/app/build.gradle` for every upload.

## What's intentionally out of scope for v1 (spec §10)

Live audio remixing/stem-muting by mood · backend/leaderboards (local storage only) ·
>5 songs · multiplayer · hold-notes (the schema's `type` field already supports `"hold"`,
no v1 chart uses it). These are noted in code comments where relevant, not half-built.
